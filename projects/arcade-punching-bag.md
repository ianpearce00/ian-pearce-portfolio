# Arcade Punching Bag

**Role:** Mechanical Design and Fabrication Team Member  
**Organization:** Rutgers TASA  
**Date:** March 2025–April 2025  
**Technologies:** Arduino, accelerometer, servo motors, Liquid Crystal Display (LCD), magnetic lock, battery, ANSYS

## Project overview

The Arcade Punching Bag is a fully automated arcade-style punching machine that integrates mechanical structure, impact sensing, electronic control, display output, and automated release mechanisms. The machine was designed to measure a user’s strike, convert the sensor data into a score from 0 to 999, and control the complete operating sequence through an Arduino-based system.

The project required coordination between mechanical, electrical, sensing, and dynamic control systems. The final system locked the punching bag after impact, processed accelerometer data, displayed a score, and released the bag after the user pressed a release button.

## System requirements

The machine was designed to:

- Capture user input from a punch
- Secure the punching bag after it was struck
- Extract impact data from the accelerometer
- Convert the impact data into a score from 0 to 999
- Display the score on an LCD
- Release the punching bag when the user pressed a button
- Operate the locking and release sequence automatically
- Maintain structural integrity under repeated impacts

The system had to coordinate high-force mechanical input with low-voltage electronic controls while fitting all electrical components within the physical constraints of the machine structure.

## System operation

The operating sequence was designed as an automated cycle:

1. A user strikes the punching bag.
2. The impact causes the system to lock the punching bag in place.
3. The Arduino reads data from the accelerometer.
4. The impact data is processed and converted into a score from 0 to 999.
5. The score is displayed on the Liquid Crystal Display.
6. The user presses the release button.
7. Servo motors pull a latch open.
8. The magnetic lock deactivates and releases the punching bag.

This sequence allowed the machine to transition from impact measurement to scoring and then back to its ready state without requiring manual mechanical intervention between users.

## Mechanical design and structural analysis

The machine’s structural frame was designed using conservative loading assumptions to account for repeated impacts. ANSYS was used to identify high-stress zones in the structure and evaluate whether the design could withstand the expected loading conditions.

The structural design incorporated safety factors intended to keep predicted stresses well below the levels that would induce fracture. The analysis helped identify areas requiring attention before fabrication and supported design decisions intended to improve long-term performance.

The electrical system was also arranged within the available mechanical envelope. This required fitting the Arduino, accelerometer, servo motors, LCD, magnetic lock, battery, and associated wiring into the structure without interfering with the punching-bag mechanism or moving components.

## Locking and release mechanism

The magnetic lock activated after the punching bag was struck, securing the bag while the system measured and displayed the result. Once the release button was pressed, the servo motors pulled a latch open and the magnetic lock deactivated.

During testing, excessive impact force sometimes caused the magnetic lock to fail to capture the bar reliably. To address this, the team added a latch that helped keep the bar close to the magnetic lock. Keeping the bar near the lock allowed the magnetic force to engage more consistently after high-force impacts.

This modification improved the reliability of the lock-and-release sequence without requiring the user to manually reposition the punching bag.

## Electronics and controls

The primary electronic components included:

- Arduino controller
- Accelerometer
- Servo motors
- Liquid Crystal Display
- Magnetic lock
- Battery
- User-operated release button

The Arduino coordinated the sensor input, score calculation, LCD output, magnetic-lock state, servo operation, and release-button input. The system was programmed to respond to the sequence of events generated by each punch and subsequent release command.

## Impact measurement and score display

The accelerometer generated data in response to the punching-bag impact. The Arduino processed this data and converted it into a user-facing score between 0 and 999.

One of the main controls challenges involved displaying the accelerometer data in a useful linearized form on the LCD. The initial code found through the Arduino IDE library did not directly provide the required output behavior. The team iterated on the code to transform the raw sensor response into a more consistent score-display format.

This required adjusting the software logic so that changes in the sensor signal produced an understandable progression on the LCD rather than an unsuitable or difficult-to-interpret output.

## Testing and iteration

Testing focused on both the structural response to impact and the reliability of the automated operating sequence. The team evaluated:

- Structural response to repeated impacts
- Lock engagement after the punching bag was struck
- Latch operation
- Servo-driven release behavior
- Magnetic-lock deactivation
- Accelerometer data capture
- Score calculation
- LCD display behavior
- Overall system reset and readiness for the next user

Testing identified two major issues. First, excessive impacts could prevent the magnetic lock from capturing the bar. The team added a latch to keep the bar near the lock and improve engagement. Second, the initial accelerometer output was not displayed linearly on the LCD, requiring multiple iterations of the Arduino code.

## Engineering challenges and solutions

### Challenge: Reliably capturing the punching bag after high-force impacts

Excessive impact force could move the bar too far from the magnetic lock, preventing the lock from engaging.

**Solution:** The team added a latch that kept the bar close to the magnetic lock, allowing the magnetism to act reliably after the bag was struck.

### Challenge: Converting sensor data into a useful score

The initial accelerometer data was not displayed on the LCD in a sufficiently linear or user-friendly fashion.

**Solution:** The Arduino code was iterated beyond the baseline code available through the Arduino IDE library. The revised logic processed the sensor data into a more consistent score range from 0 to 999.

### Challenge: Integrating electrical components into the mechanical structure

The Arduino, sensor, actuators, LCD, lock, battery, and wiring had to fit within the physical machine while preserving the operation of the punching-bag mechanism.

**Solution:** The electrical system was modified and arranged to fit within the structural constraints of the machine without interfering with the mechanical locking and release sequence.

### Challenge: Designing for repeated impact loading

The frame needed to withstand repeated impacts without fracture or unacceptable deformation.

**Solution:** ANSYS was used to identify high-stress zones. Conservative safety factors were applied so that predicted stresses remained well below the level expected to cause fracture.

## Results

The final machine provided:

- An automated punch-to-score operating sequence
- Impact sensing through an accelerometer
- A displayed score ranging from 0 to 999
- Automatic locking after the punching bag was struck
- Servo-actuated latch release
- Magnetic-lock deactivation through a release button
- Structural analysis using ANSYS
- An iteratively refined Arduino control system
- Integration of mechanical, electrical, sensing, and dynamic control systems

## Lessons learned and future improvements

This project demonstrated the importance of treating mechanical and electrical systems as an integrated design problem. A reliable control sequence depended not only on Arduino programming, but also on the physical relationship between the latch, bar, and magnetic lock.

The project also reinforced the importance of testing under realistic and excessive conditions. The magnetic-lock issue was not fully apparent under lower-force tests, but became clear when the punching bag was struck with greater force. Similarly, sensor data required practical calibration and software iteration before it could be presented effectively to a user.

Future improvements could include:

- Developing a formal calibration procedure for converting impact data to score
- Recording repeatability and accuracy across multiple impact levels
- Adding a more robust enclosure for the electrical components
- Improving the mechanical alignment and adjustability of the locking mechanism
- Documenting the ANSYS loading assumptions, mesh, and safety-factor results
- Adding a reset indicator or ready-state display
- Testing the system over a larger number of repeated impact cycles
